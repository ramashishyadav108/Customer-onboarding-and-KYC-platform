# E4-S4: Stubbed notifications fire at each lifecycle transition

- **Epic:** E4 - Manual Review, Decisions and Account Creation (Sprint 4)
- **Layer:** Service
- **Group:** F
- **depends_on:** E1-S4, E2-S4
- **Covers:** AC-09, NFR-03

## Description

No real channel exists. A notification stub records one event per transition and document rejection, and the prospect reads them in the portal.

## Acceptance Criteria

1. Every state transition (INITIATED on lead creation, DOCS_SUBMITTED, SCREENED, CLASSIFIED, APPROVED, REJECTED, MANUAL_REVIEW) records exactly one Notification (case_id, event, template, UTC timestamp) through the stub sender.
2. A document rejection by an analyst records a DOC_REJECTED notification containing the checklist item code and reason code.
3. GET /api/v1/cases/{case_id}/notifications returns the owning prospect's notifications newest first; another prospect gets 403.
4. Notification records and log lines reference the contact only by masked value (last 2 characters) and never contain plaintext phone or email.
5. If the stub sender raises an error, the transition still commits, and the failure is logged with correlation_id and case_id.
