# E4-S2: Account creation is stubbed on approval

- **Epic:** E4 - Manual Review, Decisions and Account Creation (Sprint 4)
- **Layer:** Service
- **Group:** B
- **depends_on:** E1-S4
- **Covers:** AC-07, NFR-02

## Description

No core banking integration exists. A stub service produces a deterministic synthetic account number for an approved case.

## Acceptance Criteria

1. create_account(case_id) returns a synthetic account number of the form SAV, CUR or NRE followed by 12 digits derived deterministically from the case_id, matching the case's product.
2. Account creation for a case that is not APPROVED raises InvalidOnboardingStateException and creates no row.
3. Calling create_account twice returns the same account number and leaves exactly one account row.
4. The account table is append-only with case_id, product, account_number and UTC created_at, and account creation makes no network call (test runs with sockets disabled).
5. Account creation appends an audit entry ACCOUNT_CREATED with case_id and the account number masked to its last 4 digits.
