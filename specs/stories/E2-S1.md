# E2-S1: Prospect can upload KYC documents against checklist items

- **Epic:** E2 - Document Upload and Classification Stub (Sprint 2)
- **Layer:** API
- **Group:** D
- **depends_on:** E1-S3, E2-S3
- **Covers:** AC-02, AC-03, NFR-02, NFR-03

## Description

The prospect uploads one file per checklist item. Each upload is stored with a checksum, classified by the stub classifier, and shown back with its status.

## Acceptance Criteria

1. POST /api/v1/cases/{case_id}/documents (multipart: checklist_item, file) returns 201 with document_id, version 1, checklist_item, doc_class and status VERIFIED or FLAGGED from the classifier.
2. Only PDF, JPG and PNG files up to 5 MB are accepted; another type returns 415 and a larger file returns 413, and neither is stored.
3. A checklist_item not present in the case's product checklist returns 422 with error code UNKNOWN_CHECKLIST_ITEM.
4. GET /api/v1/cases/{case_id}/documents lists the current version of each uploaded item with status, doc_class and classification reason code.
5. Each stored document records SHA-256 checksum, size and a sanitised file name; a file name such as ../../etc/passwd.pdf is stored as a safe name and never written outside the upload directory; file content and names never appear in logs.
6. A prospect can upload only to their own case (403 otherwise); a kyc-analyst can list documents of any case but cannot upload.
