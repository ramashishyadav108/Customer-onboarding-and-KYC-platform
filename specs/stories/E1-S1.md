# E1-S1: Platform exposes health, structured logs, typed config and migration guard

- **Epic:** E1 - Lead Capture, Foundation and Checklist (Sprint 1)
- **Layer:** Config
- **Group:** A
- **depends_on:** []
- **Covers:** NFR-03, NFR-05, NFR-06, NFR-07

## Description

Every later story depends on a running service with observable, PII-safe logging. This story delivers the FastAPI skeleton, /health, JSON logging with correlation IDs, redaction of PII, typed environment config, and a guard that keeps migrations append-only.

## Acceptance Criteria

1. GET /health returns HTTP 200 with body {"status":"ok"} within 1000 ms of process start.
2. Every log line is single-line JSON with keys timestamp, level, correlation_id, message; correlation_id is taken from the X-Correlation-ID request header or generated as a UUID4 when absent, and echoed in the X-Correlation-ID response header; lines emitted for a case-scoped request also contain case_id.
3. A log filter redacts PAN (pattern AAAAA9999A), 12-digit Aadhaar, phone numbers, email addresses, income and occupation values: a test logs a record containing synthetic values of each and asserts none appear in plaintext in output.
4. Settings load from environment variables into a typed Settings object; starting with DATABASE_URL unset fails with an error message naming DATABASE_URL.
5. A migration guard compares the SHA-256 of every applied migration file with a committed manifest; editing or deleting an existing migration file makes the guard test fail, while adding a new file passes.
