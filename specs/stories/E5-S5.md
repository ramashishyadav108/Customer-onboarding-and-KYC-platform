# E5-S5: Architecture and compliance rules are enforced as automated tests

- **Epic:** E5 - Reports and Admin Console (Sprint 5)
- **Layer:** Service
- **Group:** J
- **depends_on:** E3-S2, E4-S1, E4-S3
- **Covers:** NFR-02, NFR-03, NFR-05, NFR-08

## Description

The NFR-08 rules become permanent tests that fail the build if regressed, together with layering, append-only and PII checks.

## Acceptance Criteria

1. Test: a published rule set cannot be updated or deleted through service, repository or raw SQL.
2. Test: an APPROVED case cannot be modified through any service entry point (upload, profile, screening, classification, decision, transition, reclassify).
3. Test: a risk-band reassignment without an override audit record fails, and with a record succeeds, at service level.
4. Test: imports follow Types, Config, Repository, Service, API one way; an AST scan finds zero upward imports in the backend.
5. Test: every append-only table (state history, audit log, documents, classification results, screening results, risk assessments, decisions, overrides, accounts, notifications) rejects UPDATE and DELETE.
6. Test: an end-to-end happy-path run and a manual-review run emit logs containing none of the synthetic PAN, Aadhaar, contact, income or occupation values used.
