# E3-S2: Risk rule sets are versioned with integer weights and immutable once published

- **Epic:** E3 - Screening and Risk Classification (Sprint 3)
- **Layer:** Repository
- **Group:** A
- **depends_on:** []
- **Covers:** AC-06, NFR-01, NFR-05, NFR-08

## Description

The rule engine's data model. Proposed v1 rule set: weights age 20, income 25, occupation 30, geography 25 (sum 100); all factor points are integers 0-100; thresholds LOW 0-29, MEDIUM 30-59, HIGH 60-100. See specs/classification_spec.md.

## Acceptance Criteria

1. A RuleSet has an integer version, status DRAFT or PUBLISHED, integer weights for age, income_band, occupation_category and geography, integer points tables for each factor, income band boundaries, and integer thresholds low_max and medium_max.
2. Weights, points and thresholds reject non-integer values: a float or Decimal such as 0.25 raises a ValidationError, and a static scan of the risk modules finds no float type or float literal.
3. Publishing a DRAFT sets status PUBLISHED and published_at; any later update or delete of a PUBLISHED rule set raises PublishedRuleSetImmutableError at service level and is rejected by a database trigger.
4. A new version is created only as a DRAFT copy of the latest version with version = max(version)+1; earlier versions stay queryable and unchanged.
5. Publish fails with RULESET_INVALID when weights do not sum to 100 or thresholds are not strictly ascending (low_max < medium_max < 100).
6. A migration seeds published v1 with weights age 20, income 25, occupation 30, geography 25 and thresholds low_max 29, medium_max 59.
