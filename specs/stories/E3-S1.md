# E3-S1: Case name is screened against the static AML/PEP watchlist

- **Epic:** E3 - Screening and Risk Classification (Sprint 3)
- **Layer:** Service
- **Group:** F
- **depends_on:** E2-S2, E1-S4
- **Covers:** AC-05, NFR-02, NFR-05

## Description

Screening compares the applicant name to a synthetic watchlist. A hit never blocks the pipeline mechanically; it sets a routing flag with a reason code so the decision step sends the case to MANUAL_REVIEW.

## Acceptance Criteria

1. POST /api/v1/cases/{case_id}/screen (kyc-analyst or admin) on a DOCS_SUBMITTED case moves it to SCREENED and stores a ScreeningResult (case_id, hits, watchlist_version, UTC timestamp).
2. Matching is case-insensitive and ignores punctuation, repeated whitespace and token order: 'Test  Person-One', 'PERSON ONE TEST' style variants match the entry 'Test Person One' or any of its aliases; a different name does not match.
3. A hit records entry_id, list_type (AML or PEP) and reason_code (AML_HIT or PEP_HIT) and sets requires_manual_review true on the result; a case with a hit can never be auto-approved.
4. With no hit the result has an empty hits list, requires_manual_review false, and the case is still SCREENED.
5. The watchlist is seeded by an append-only migration with at least 10 synthetic entries (5 AML, 5 PEP); screening results are append-only, and re-screening appends a new row rather than updating.
6. Screening a case in any state other than DOCS_SUBMITTED raises InvalidOnboardingStateException, except a repeat call on a SCREENED case with the same watchlist version which returns the existing result without a new transition.
