# E3-S3: Cases are classified LOW, MEDIUM or HIGH risk by the versioned rule engine

- **Epic:** E3 - Screening and Risk Classification (Sprint 3)
- **Layer:** Service
- **Group:** G
- **depends_on:** E3-S1, E3-S2
- **Covers:** AC-06, AC-04, NFR-01, NFR-02

## Description

Score = sum(points[factor] * weight[factor]) // 100 using integers only. Age comes from date of birth, income band from annual income, geography from country_code via a static map. The assessment records the rule version used.

## Acceptance Criteria

1. With published v1: age 35, income 3,000,000, SELF_EMPLOYED, IN scores 16 LOW; age 65, income 12,000,000, BUSINESS_OWNER, foreign standard-risk country scores 45 MEDIUM; age 65, income 12,000,000, CASH_INTENSIVE, foreign high-risk country scores 72 HIGH.
2. Band boundaries are exact: score 29 is LOW, 30 is MEDIUM, 59 is MEDIUM and 60 is HIGH.
3. Scoring uses integer floor division only; a property test over 1,000 random valid profiles returns an int score between 0 and 100 with no float anywhere in the call path.
4. Each evaluation appends a RiskAssessment (case_id, score, band, rule_version, per-factor breakdown); publishing a later rule version does not change any stored assessment.
5. POST /api/v1/cases/{case_id}/classify on a SCREENED case stores the assessment and moves it to CLASSIFIED; on any other state it returns 409 INVALID_STATE.
6. If a profile field needed by the rules is missing, classification returns 422 MISSING_PROFILE_FIELD naming the field and the state does not change.
