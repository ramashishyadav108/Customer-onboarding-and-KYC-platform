# E3-S4: Admin can manage rule sets and the watchlist through the API

- **Epic:** E3 - Screening and Risk Classification (Sprint 3)
- **Layer:** API
- **Group:** G
- **depends_on:** E3-S1, E3-S2, E1-S2
- **Covers:** AC-06, AC-05, NFR-02, NFR-04

## Description

Admins draft and publish rule versions and maintain the synthetic watchlist. Nothing published or recorded is edited in place.

## Acceptance Criteria

1. POST /api/v1/admin/rule-sets creates a DRAFT copy of the latest version, PUT /api/v1/admin/rule-sets/{version} edits a DRAFT, POST .../publish publishes it; all three return 403 for non-admin roles.
2. PUT on a PUBLISHED rule set returns 409 RULESET_IMMUTABLE and leaves stored values unchanged.
3. JSON numbers with a fractional part in any weight, points or threshold field (for example 0.25) are rejected with 422.
4. POST /api/v1/admin/watchlist adds an entry (name, aliases, list_type AML or PEP); removal is by POST .../deactivate which appends a deactivation row; screening uses only entries active at screening time.
5. GET /api/v1/admin/rule-sets lists every version with status, published_at and author; every admin change appends an audit entry with actor and event type.
