# E2-S3: Stub classifier returns canned results for known fixture files

- **Epic:** E2 - Document Upload and Classification Stub (Sprint 2)
- **Layer:** Service
- **Group:** B
- **depends_on:** E1-S1
- **Covers:** AC-03, NFR-02, NFR-05

## Description

No OCR is performed. The classifier decides by file-name convention so tests are deterministic. Rules live in a migration-seeded table so they are versioned and append-only.

## Acceptance Criteria

1. Files named pan_*, aadhaar_*, passport_* and utility-bill_* (extensions pdf, jpg, png) classify as PAN, AADHAAR, PASSPORT and UTILITY_BILL respectively with status VERIFIED and confidence_bp 9500; photograph_*, gst-certificate_* and visa_* classify as PHOTOGRAPH, GST_CERTIFICATE and VISA with the same status and confidence.
2. A file name matching no rule returns doc_class UNRECOGNISED, status FLAGGED and reason_code DOC_UNRECOGNISED.
3. If the classified class is not in the accepted classes of the target checklist item (for example utility-bill_1.pdf uploaded as ID_PROOF), the result is status FLAGGED with reason_code DOC_CLASS_MISMATCH.
4. Classification is deterministic and uses integers only: classifying the same file twice returns identical results, and confidence is an integer number of basis points.
5. Every classification is appended as a new row (document_id, result, rule_version, UTC timestamp); no update or delete of classification rows is possible, and classification rules come from a migration-seeded table changed only by new migrations.
