# E4-S3: Compliance officer can override manual review with an audited reason

- **Epic:** E4 - Manual Review, Decisions and Account Creation (Sprint 4)
- **Layer:** API
- **Group:** I
- **depends_on:** E4-S1, E4-S2, E1-S2
- **Covers:** AC-08, NFR-02, NFR-04, NFR-08

## Description

Only compliance officers decide MANUAL_REVIEW cases. Every override and every risk-band reassignment carries a reason code and leaves an append-only audit record.

## Acceptance Criteria

1. GET /api/v1/review-queue returns MANUAL_REVIEW cases oldest first with case_id, product, reason_code and age_minutes; it returns 403 for every role except compliance-officer.
2. POST /api/v1/cases/{case_id}/override with decision APPROVE or REJECT, a reason_code from the controlled list and an optional comment moves the case to APPROVED or REJECTED; a missing or unknown reason_code returns 422 and changes nothing.
3. Only compliance-officer can override: analyst, admin and prospect receive 403; an override on a case not in MANUAL_REVIEW returns 409 INVALID_STATE.
4. Each override appends an Override row (case_id, actor, previous_state, decision, reason_code, comment, rule_version, UTC timestamp) and an audit entry OVERRIDE_APPLIED; rows cannot be updated or deleted.
5. An APPROVE override creates the stub account and returns its account number; a REJECT override creates none.
6. POST /api/v1/cases/{case_id}/reclassify (compliance-officer) with a new risk band and reason_code appends a new RiskAssessment and an audit record; without a reason_code it returns 422 and the original band stays in force.
