# E2-S4: Prospect can re-upload missing or rejected documents without restarting

- **Epic:** E2 - Document Upload and Classification Stub (Sprint 2)
- **Layer:** API
- **Group:** E
- **depends_on:** E2-S1, E2-S3
- **Covers:** AC-09, NFR-02

## Description

A kyc-analyst may reject a document with a reason. The prospect replaces any missing, flagged or rejected document as a new version. The case, its case_id and its state do not restart.

## Acceptance Criteria

1. POST /api/v1/cases/{case_id}/documents/{document_id}/reject by a kyc-analyst with a reason_code sets that document's status to REJECTED and appends an audit entry; other roles get 403.
2. While the case is INITIATED, DOCS_SUBMITTED or MANUAL_REVIEW, POST documents for an already-filled checklist item creates version n+1; the earlier version is retained and marked superseded, never overwritten.
3. Re-upload leaves the case_id and state unchanged and adds no state-history row; a re-upload on an APPROVED or REJECTED case returns 409 CASE_LOCKED.
4. A replacement document is classified again on upload, and a replacement for a REJECTED or FLAGGED document clears that item's action_required flag when the new result is VERIFIED.
5. GET /api/v1/cases/{case_id} returns an action_required array listing each checklist item that is missing, FLAGGED or REJECTED together with its reason code.
